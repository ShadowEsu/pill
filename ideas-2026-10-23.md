## Honest read of the three starting ideas
1. **Phone-camera 3D building scan + earthquake/fire stability.** 3D capture without LiDAR = photogrammetry / Gaussian splatting on a rented GPU (Vultr or DigitalOcean, both MLH tracks). Doable for one floor or room in 36 h, not a building. Earthquake/structural stability from a video is not credible and judges (Hyphenate, main criteria) ask what is real vs simulated. **Keep the scan, swap the analysis to fire-safety inspection** (checklists are public: blocked exits, extension-cord daisy chains, extinguisher placement, exit signs). → Idea C.

3. **Phone vibration motor makes it stand/spin.** Fun for Most Creative only; no user, no startup. Fold into a demo gag at most.

## The three to pick from

### A. Custody (recommended)
**One line:** a box that proves nobody opened, dropped, overheated or rerouted what's inside, and can show that proof to anyone.
**Named community:** lab couriers and evidence technicians (ask one at the venue: any bio/chem student who ships samples).
**Tracks (7–8):** Best Hardware · MLH Solana (supply chain) · MLH Tiger Data (IoT time-series) or SpacetimeDB (live state across box, phone, dashboard) · Armadin Best Security · Convex ($5K, reactive backend for the dashboard) · Anthropic (Claude writes the incident report, knows when it is unsure) · MLH Gen AI · .Tech domain. Coinbase x402 only if every member clears the 18+/verified-account gate.
**Demo moment:** judge picks the box up, opens the lid; the dashboard flips to "breached 14:02:31, light + lid + 2.1 g drop", a Solana tx hash appears, Claude's one-paragraph report names which custody rule was broken.
**Local AI:** Pi buffers and signs events offline (that is the feature: custody survives no Wi-Fi); event classification is rules + a tiny on-device model; Claude only for the report, with a local Ollama fallback on the laptop.
**3 hardest parts:** (1) sensors: Arduino starter kits have tilt switch, photoresistor, TMP36, piezo but usually no IMU; grab an MPU-6050 and a Pi camera at the hardware booth tonight, or use a phone's DeviceMotion API as the IMU; (2) offline-first event log with hash chain → batch anchor on Solana devnet when online; (3) saying honestly what is on-chain (hashes) and what is not (raw data).
**Hours (37 left):** Fri 20:00–23:00 sensors wired, raw readings streaming to laptop · 23:00–03:00 event detection (open/drop/tilt/heat/move), hash chain, Tiger Data or SpacetimeDB schema · Sat 08:00–12:00 Solana devnet anchoring + explorer link, dashboard live · 12:00–16:00 Claude incident report, phone view, Convex workshop 4 PM · 16:00–22:00 enclosure, polish, 3 scripted scenarios, draft Devpost by 22:00 · Sun 00:00–03:00 video (open with the moment), README "where each tool is used" · sleep · 07:00–08:30 final submit.

## Wi-Fi / local AI
Personal hotspots and routers get confiscated (organiser email). USB tethering a phone to one laptop is quieter but check the rule first. Design every demo to run with the network down: Pi + laptop over a direct Ethernet cable or the Pi's own Wi-Fi AP, local Ollama (Llama 3.2 3B / Qwen 2.5 7B) on the laptop for the fallback narration, Claude when online. Judges reward "it still works" more than the model.
