# Composio × Figma: commands

Connector: Composio CLI 0.5.0 at `~/.local/bin/composio`, toolkit `figma`, active account `figma_yoker-tackle` (two older `preston-figma` connections are EXPIRED, so always pass `--account figma_yoker-tackle`). What it can do: read files, comment, set variables, dev resources, render images, extract tokens. What it cannot do: create layers, frames or slides; that is why the plugin exists. The REST tools read **Design** files only (`figma.com/design/<KEY>`), not Slides or FigJam.

Set once per shell after the teammate runs the plugin in a Design file and pastes the URL into `LINKS.md`:

```sh
C=~/.local/bin/composio; A="--account figma_yoker-tackle"
KEY=<file key from figma.com/design/<KEY>/...>
```

## (b) After the plugin has run: NOT RUN YET (needs `KEY`)

1. File metadata (pages and top-level frames; depth 2 keeps it small):
   ```sh
   $C execute FIGMA_GET_FILE_JSON $A -d "{\"file_key\":\"$KEY\",\"depth\":2}" > figma/file-meta.json
   ```
2. Comment with the build time (the plugin prints the time and seconds when it finishes; paste them in):
   ```sh
   $C execute FIGMA_ADD_A_COMMENT_TO_A_FILE $A -d "{\"file_key\":\"$KEY\",\"message\":\"Generated by Pill → Figma plugin at <time> from deck.json (build-deck.mjs). Source: ~/calhacks-13/figma\"}"
   ```
3. Dev resources: link every app-screen frame to its route's source file. The plugin names those frames `App · <file>` and stores the route; `build-deck.mjs` wrote the same mapping into `deck.json`. This builds the request from the file JSON and runs it:
   ```sh
   node -e '
   const m=require("./figma/file-meta.json"), d=require("./figma/deck.json");
   const items=new Map(d.design.appScreens.groups.flatMap(g=>g.items).map(i=>[i.name,i]));
   const out=[]; (function w(n){ if(!n||typeof n!=="object")return; if(n.name&&items.has(n.name)&&n.id){const i=items.get(n.name); out.push({file_key:process.env.KEY,node_id:n.id,name:"Route "+i.route+" · "+i.source,url:"https://github.com/<owner>/<repo>/blob/main/"+i.source});} Object.values(n).forEach(w); })(m);
   require("fs").writeFileSync("figma/dev-resources.json",JSON.stringify({dev_resources:out}));
   console.log(out.length,"dev resources");'
   $C execute FIGMA_CREATE_DEV_RESOURCES $A -d @figma/dev-resources.json
   ```
   Replace `<owner>/<repo>` with the public repo once it exists; until then use the live app URL plus the route (`https://<app>.vercel.app` + route) as `url`. If the file JSON at depth 2 does not reach the frames, rerun step 1 with `"depth":3`.
4. Thumbnails for Devpost (the 16 deck frames on the "Deck" page, PNG at 1×):
   ```sh
   node -e '
   const m=require("./figma/file-meta.json"); const out=[];
   (function w(n){ if(!n||typeof n!=="object")return; if(n.type==="FRAME"&&/^\d\d · /.test(n.name||""))out.push({node_id:n.id,file_name:n.name.slice(0,2)+".png",format:"png"}); Object.values(n).forEach(w); })(m);
   require("fs").writeFileSync("figma/thumbs-req.json",JSON.stringify({file_key:process.env.KEY,scale:1,images:out}));
   console.log(out.length,"frames")'
   mkdir -p figma/thumbs && $C execute FIGMA_DOWNLOAD_FIGMA_IMAGES $A -d @figma/thumbs-req.json > figma/thumbs/result.json
   ```
   The tool returns download paths or URLs in `result.json`; move or `curl -o` them into `figma/thumbs/`.
5. Tokens back to CSS (the reverse handoff in STAGE-LOG Stage 3):
   ```sh
   node figma/tokens-from-figma.mjs $KEY --account figma_yoker-tackle          # all tokens as :root
   node figma/tokens-from-figma.mjs $KEY --account figma_yoker-tackle --diff   # only what differs from pill/web/src/index.css
   ```

Record each step's result and minutes in `STAGE-LOG.md` where it says `[fill after running]`.
